Low - Level Design (LLD)

The LLD defines the strict data structures and deterministic node logic required for production reliability.


1. State Schema (AgentState) :
   -------------------------

   The state is managed via a Pydantic BaseModel to ensure type safety throughout the graph execution.

     StateField                    DataType                         Purpose
     ----------                    --------                         -------

   1. messages                      list[BaseMessages]               CoreLangGraph History(Automatically appended)
   2. raw_service_report            str                              The unedited customer service report
   3. sanitized_report              str                              The text after Presidion Redaction
   4. retrieved_warranty_policies   list[Dict]                       The Context injected from Qdrant Hybrid Search
   5. warrant_claim_assessment      str                              The final output staructured by the LLM
   6. error_count                   int                              Tracks consecutive API or tool failures for circuit-breaking


2 . Node definitions : 
    ----------------

    Node Name                     processing logic
    ---------                     ----------------

    sanitize_data                 Parses raw_service_report using Presidio. Masks names, locations,
                                  and VINs. Validates edge cases and updates sanitized_report.

                        
    query_compliance_db            Formats a search query based on the sanitized issue. Retrieve matching 
                                  regulatory documents from Qdrant. Updates retrieved_warranty_policies.


    claim_assessment               Injects sanitized_report and retrieved_warranty_policies in to a structured \
                                  prompt. Calls a hosted LLM to generate the warrant_claim_assessment.


    error_fallback                 Triggered by conditional routing if toll calls time out.
                                  Increments error_count. If error_count < 3 ,
                                  requests a retry . If >=3 , halts execution gracefully.



3. WorlFlow Routing : 
   ----------------

   1. Entry Point         : Starts at sanitize_data.
   2. Standard Flow       : sanitize_data -> query_compliance_db -> claim_assessment.
   3. Conditional Routing : Post - query_compliance_db, if an exception is caught , route to
                            error_fallback. error_fallback routes back to query_compliance_db or END
                            based on error_count.
   4. Interrupt Boundary  : Post - claim_assessment , the checkpoint pauses the graph. A user must hit
                           a specifc API endpoint tp approve the claim_assessment , befor the graph
                            routes to END.
